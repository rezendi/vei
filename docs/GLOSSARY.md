# Glossary

Every term of art used across VEI docs, defined once. Entries are alphabetical.

---

**Approval rule** — a typed rule in workspace governor config that names a surface or tool and declares whether writes require hold-for-approval, deny, or allow. Approval rules live in policy profiles.

**Balanced operator score** — a fixed query-time readout computed from predicted future heads: `mean(1-risk, commercial_position, 1-strain, trust, 1-drag)`. Useful for sorting candidate actions, but it is not a learned JEPA target or a universal preference label.

**Blast radius** — a provenance report showing which company objects, surfaces, and actors were touched or affected by a selected event or agent action.

**Blueprint / BlueprintAsset / CompiledBlueprint** — the three layers of scenario authoring. A `BlueprintAsset` is the raw authoring root (scenario templates, capability seeds, facade requirements). A `Blueprint` compiles that asset into a scenario, facades, workflow, contract, and run defaults. A `CompiledBlueprint` is the resolved facade/state graph plus run defaults, ready to hydrate a `WorldSession`.

**Branch / branch point** — a moment in a company's event history chosen as the divergence point for a what-if experiment. VEI forks the world state at that event and compares the historical future against counterfactual alternatives.

**Business Task Spec** — a declarative, evidence-backed description of recurring business work. It names the objective, context requirements, required evidence, constraints, policies, acceptable outputs, rubrics, labels, examples, and escalation points. It does not require ordered steps; deterministic workflows, contracts, and RL packages are downstream specializations. Its `metadata` field is an escape hatch for company-specific or experimental context, not a place to hide fields that should become part of the typed schema.

**Candidate action / candidate posture** — a proposed alternative move at a branch point. Candidate actions are generated by an LLM, by deterministic templates, or by a human. Each action carries an action path, review path, communication boundary, and follow-up trigger. A "posture" is the broad stance (e.g. defensive, active, fast, escalated, hold).

**CanonicalEvent** — the frozen v1 event envelope (`vei.events`) that is the single source of truth on the event spine. All other state (StateStore, run timelines, connector receipts) is derived from canonical events.

**Capability domain / capability graph** — the public ontology that groups enterprise surfaces into domains: `comm_graph` (Slack, Mail), `doc_graph` (Docs, Browser), `work_graph` (Tickets, Jira), `identity_graph` (Okta, HRIS), `revenue_graph` (CRM), `knowledge_graph`, `obs_graph` (SIEM, Datadog), `ops_graph` (feature flags, ERP), `data_graph` (Spreadsheet), and vertical-specific graphs (property, campaign, inventory).

**Connector** — the adapter layer routing tool calls through simulated, replay, or live backends. Policy gates classify operations as READ, WRITE_SAFE, or WRITE_RISKY.

**Contract / contract variant** — explicit success predicates, forbidden predicates, observation boundary, policy invariants, reward terms, and intervention rules for a scenario. A contract variant is an overlay on a base contract (e.g. `protect_sla` vs `protect_revenue`).

**Counterfactual** — an alternate future path computed after changing the action at a branch point. VEI supports LLM actor continuations and learned backend forecasts as two counterfactual paths.

**Doctrine packet** — an archive-derived text document describing what a company is, what is strategic, what is out of scope, and which archive citations support that reading. Generated from source evidence; carried as text in JEPA training rows.

**Dynamics backend** — the protocol (`vei.dynamics`) for forecast/learned-dynamics calls. Registered backends: `null`, `heuristic_baseline`, `reference`, `external_subprocess`.

**Episode** — a materialized replay workspace built from one selected branch point. Contains the pre-branch state, the branch event, and scheduled historical future events.

**Eval runner** — one of four runner types in the eval system: **scripted** (hardcoded behavior tree), **workflow** (declarative step graph — the reference solution), **bc** / **FrequencyPolicy** (tool-frequency heuristic from demonstrations), **llm** (real LLM agent via MCP).

**Evaluation level** — the workflow-intelligence readiness ladder: `descriptive`, `labeled`, `rubric_evaluable`, `contract_evaluable`, and `rl_packaged`. It prevents judgment-heavy workflows from being forced into deterministic contracts before the evidence supports that move.

**Event spine** — the ordered sequence of `CanonicalEvent` records that forms the single source of truth for a world, workspace, or run. Everything — state, timelines, provenance, scoring — is derived from the event spine.

**Evidence pack** — a portable export of provenance data: agent inventory, access review, blast radius, and policy replay results, serialized from the canonical event spine.

**Facade** — a typed enterprise surface grouped by capability domain (e.g. Mail, Slack, Tickets, CRM, Identity). Facades present a realistic API shape while the kernel manages underlying state.

**Frontier rank / Pareto frontier** — when JEPA scores multiple candidate actions, the Pareto frontier identifies options where no other candidate dominates across all predicted future heads. Frontier rank orders those non-dominated options; `display_rank` puts frontier options first.

**Governor / governed twin** — the runtime that sits between outside agents and enterprise-shaped routes. Manages agent registration, event ingest, approval queues, rate limiting, and policy enforcement. Write outcomes: allow, deny, or hold for approval.

**Grounding bundle** — a typed imported org/policy/incident bundle that compiles into a `BlueprintAsset`. This is how real enterprise data enters the scenario authoring pipeline.

**Heuristic baseline** — a tag-driven heuristic forecast that shifts event counts, escalations, and risk up or down from intervention tags. Not a learned model — useful as a debug and regression baseline.

**Import package** — the raw file-based intake format for offline CSV/JSON enterprise exports. Carries source manifests, mapping profiles, redaction state, and provenance anchors.

**JEPA** — Joint Embedding Predictive Architecture. The learned world-model backend that predicts a bundle of factual future heads (risk, commercial position, trust, drag, etc.) from doctrine text + pre-branch state + candidate action. Trained on canonical event sequences via `vei whatif benchmark`.

**Kernel** — see **WorldSession**.

**Knowledge graph** — typed knowledge assets, edges, composition requests, compaction policies, and validation helpers. The deterministic baseline plus bounded LLM authoring surface for notes, transcripts, SOPs, pricing, and deliverables.

**Knowledge composition** — authoring a grounded artifact (proposal, brief, etc.) from the knowledge graph, with citations, freshness checks, and contract scoring.

**MCP transport** — the Model Context Protocol transport layer. VEI supports **stdio** (default for dev/CI) and **SSE** (HTTP streaming). The router exposes enterprise tools over these transports.

**Policy profile** — a named set of permissions, allowed surfaces, and approval rules assigned to a governed agent. Built-in profiles ship with default restrictions; workspace config can override.

**Policy replay** — re-running a sequence of recorded events through current or modified policy rules to see which actions would be allowed, denied, or held.

**Predicted future heads** — the bundle of signals JEPA predicts for a candidate action: evidence heads (outside spread, fanout, review loops, delays), business heads (enterprise risk, commercial position, org strain, stakeholder trust, execution drag), and future-state heads (regulatory exposure, liquidity stress, governance response, evidence control, external confidence pressure).

**Provenance** — the read-side reporting surface (`vei.provenance`) that builds timelines, activity graphs, access reviews, blast-radius reports, policy replay reports, evidence packs, and OTel exports from the canonical event spine.

**Reference backend** — the repo-local PyTorch checkpoint (`data/enron/reference_backend/`) trained on canonical event sequences. The shipped fresh-clone learned path.

**Replay** — scheduling recorded historical events into the world kernel so the original timeline plays out inside VEI's deterministic engine.

**Run** — a single execution of a workflow, benchmark, demo, showcase, or suite against a workspace. Carries a canonical manifest, append-only event stream, snapshots, and contract summary.

**Scenario / scenario variant** — a seeded enterprise world plus manifest metadata. A scenario variant is an overlay that injects faults (vendor no-show, deadline compression, capacity fragmentation) onto the same base world.

**Skill map** — a set of evidence-backed, replay-checked company-specific agent skills compiled from a normalized company bundle. Skills are `draft` by default and carry candidate type, triggers, output artifacts, usefulness scores, and approval boundaries.

**Snapshot** — a branchable world-state checkpoint. Snapshots let you fork, compare, or restore world state at any point.

**Strategic state point** — the user-facing counterfactual interface. An as-of date + state dossier from pre-as-of evidence, plus candidate actions proposed by an LLM or human. JEPA scores each candidate's predicted future vector. This is how VEI turns learned predictions into decision-support tables.

**Structure view** — the event-derived read model (`vei.structure`) with inferred entities, case clusters, relations, timelines, and open ambiguities. Agents use it to understand the world before acting.

**Studio** — the local FastAPI + SSE playback/debug UI. Presents the kernel through Company, Crisis, Outcome, Audit, and Control tabs. Default port: 3011 (quickstart) or 3055 (standalone).

**Surface** — a typed enterprise system exposed through the kernel: Mail, Slack, Tickets, Docs, CRM, Identity, Browser, ServiceDesk, etc.

**Twin / twin gateway** — the HTTP gateway (default port 3012) that exposes provider-shaped compatibility routes (Slack Web API, Jira REST, MS Graph, Salesforce REST) and manages governed agents.

**VEI** — the product name. VEI builds a runnable replica of any organisation or situation from real records. Package name on PyPI: `pyvei`.

**Workspace** — the file-backed project model. Contains blueprint assets, contracts, scenarios, compile records, run registries, and saved what-if bundles.

**What-if** — the historical replay and counterfactual experiment system. Normalize company records → explore → branch → materialize → compare → validate.

**Workflow candidate** — a mined recurring work pattern grouped from canonical events by thread, case, conversation anchor, actors, objects, surfaces, and timing. A candidate can be labeled and promoted into a Business Task Spec.

**WorldSession** — the deterministic world kernel: one mutable company state, one canonical event spine, typed enterprise facades, snapshots, branching, and replay. Same seed = same world.
